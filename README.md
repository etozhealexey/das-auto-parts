# Das-Auto-Parts

Оптовая платформа автозапчастей для СТО и магазинов. FastAPI + PostgreSQL, серверные шаблоны Jinja2.
Дизайн: макет на Tilda (эталонная вёрстка главной — `design-ref/home.html`).

## Память проекта

- [AGENT_CONTEXT.md](AGENT_CONTEXT.md) — договорённости, устройство приложения, состояние
  интеграций, журнал работ, результаты проверок и открытые вопросы.
- [AGENTS.md](AGENTS.md) — правила работы и обязательного обновления памяти проекта.
- Этот README — запуск, настройка и рабочие команды.

## Быстрый старт

```bash
cp .env.example .env            # при первом запуске
docker compose up -d db         # либо локальный PostgreSQL, см. ниже
uv sync
uv run alembic upgrade head
uv run python -m scripts.seed
uv run uvicorn app.main:app --reload
```

Сайт: http://localhost:8000, JSON API: http://localhost:8000/docs

Локальный PostgreSQL вместо Docker:

```bash
createuser -s dasauto && psql -c "alter user dasauto password 'dasauto'" && createdb -O dasauto dasauto
```

## Цены с autoeuro.ru

Цены берутся через официальный API v2 (https://api.autoeuro.ru/doc/v2). Ключ выдаётся юрлицам
в личном кабинете shop.autoeuro.ru (раздел API). В `.env`:

```
PRICE_PROVIDER=autoeuro
AUTOEURO_API_KEY=<ключ>
AUTOEURO_DELIVERY_KEY=        # пусто — возьмётся первый вариант из /get_deliveries
```

Без ключа работает `PRICE_PROVIDER=demo` с тестовыми предложениями, чтобы проверять интерфейс.

Схема: поиск по артикулу → `search_brands` (какие бренды выпускают деталь) → `search_items` по каждому
бренду (цена, наличие, срок, аналоги). Один поиск пользователя = 1 + число брендов запросов к API
(обычно 3–5). Исходные предложения поставщика кэшируются в таблице `price_offers` на
`PRICE_CACHE_TTL_MINUTES` минут; лимит API — 3000 поисков в сутки, поэтому кэш важен.

Ценовая политика (`app/services/pricing/policy.py`) применяется при выдаче, кэш хранит исходные цены:

```
PRICE_MARKUP_PERCENT=15   # цена клиента = цена поставщика × 1.15, округление до копейки
DELIVERY_EXTRA_DAYS=1     # срок клиента = срок поставщика + 1 день (delivery_time и delivery_time_max)
```

Цена поставщика наружу не отдаётся: шаблоны показывают только клиентскую, JSON API использует `OfferOut`.

Поставщик в выдаче — это тип предложения autoeuro: собственный склад Авто-Евро (с названием склада),
партнёрское предложение или официальный дилер. Имена партнёров API не раскрывает.

Проверить ключ и посмотреть варианты получения (delivery_key) для `.env`:

```bash
uv run python -m scripts.autoeuro_check 0446533471
```

Сроки приходят в местном времени точки получения; выбранная точка определяет часовой пояс.
В `.env` выбран пункт в Санкт-Петербурге.

## Прайс-лист и каталог

Каталог по брендам и категориям строится на прайс-листе склада autoeuro, а не на поисковом API.
Прайс — ZIP с одним CSV (UTF-8, запятая, заголовок): ~64 тыс. позиций, ~560 брендов.

Откуда берётся ссылка: кабинет autoeuro → Настройки → Прайс-лист. Там выбирается склад и формат,
после завершения генерации появляется ссылка на файл. Срок действия ссылки и автоматическое
формирование новых файлов зависят от настроек поставщика. Наше расписание проверяет готовый файл,
но не запускает его генерацию в кабинете. При 403/404 потребуется обновить ссылку в `.env`.
Ссылка содержит данные аккаунта — хранить только в `.env`. В лог пишется только хост, в запись
импорта (`price_list_imports.source`) — хост и SHA-256 полного URL.

```
PRICE_LIST_URL=<ссылка из кабинета>      # пусто — импорт выключен
PRICE_LIST_REFRESH_MINUTES=30            # как часто проверять обновление файла
PRICE_LIST_WAREHOUSE=Санкт-Петербург ЦС  # отображаемое имя склада
PRICE_LIST_REQUEST_TIMEOUT=120           # таймаут скачивания, секунд
```

Расписание: фоновый цикл в процессе приложения (`app/services/pricelist/importer.py`, `refresh_loop`)
делает первую проверку через 10 секунд после старта, затем раз в `PRICE_LIST_REFRESH_MINUTES`.
Проверка — условный запрос с `If-None-Match` по ETag последнего успешного импорта: если файл
не менялся, сервер отвечает 304 (или отдаёт файл с тем же ETag) и ничего не делается, запись
импорта не создаётся. Новый файл целиком заменяет строки своего склада в `price_list_items`
в одной транзакции (если импорт упал, остаются прежние строки); каждый запуск оставляет запись
в `price_list_imports` (статус `done`/`failed`, счётчики строк и брендов, сообщение с причинами
пропуска: нулевой остаток, некорректная цена, дубликат ключа и т. п.). Повторный запуск, пока
импорт уже идёт, пропускается. PostgreSQL advisory lock защищает и от пересечения фонового
обновления с ручным скриптом или другим процессом приложения. Пустой, повреждённый или валютный
прайс не заменяет рабочий каталог; ошибка записывается в историю. Размер скачивания ограничен
64 МиБ, распакованного CSV — 256 МиБ. Каталог и успешный статус сохраняются одной транзакцией.

Ручной импорт:

```bash
uv run python -m scripts.import_pricelist                 # скачать по PRICE_LIST_URL (учитывает ETag)
uv run python -m scripts.import_pricelist --force         # скачать, даже если файл не менялся
uv run python -m scripts.import_pricelist --file data/pricelists/PriceAE_2026-10-27.zip   # локальный ZIP или CSV
```

Скрипт печатает итог: номер и статус импорта, время и длительность, склад, имя CSV, число строк,
импортированных, пропущенных и брендов. Адрес прайса не печатается. Полный импорт реального прайса
(64 тыс. строк) занимает несколько секунд. Папка `data/` в `.gitignore`.

Цены в таблице — закупочные, как в прайсе. Наценка (`PRICE_MARKUP_PERCENT`) применяется только при показе
через `PricePolicy`, как и для предложений из API. Категория позиции выводится из названия при импорте
(`app/services/pricelist/categories.py`), бренд — из колонки «Производитель» со slug для адресов страниц.
Запросы для страниц каталога (категории, бренды, поиск с пагинацией) — `app/services/pricelist/catalog.py`.

Страницы: `/catalog`, `/catalog/brand/{slug}`, `/catalog/category/{slug}`, `/catalog/search?q=...`.
Поиск учитывает все слова в названии/бренде и нормализованные артикулы/OEM-номера. Категории
определяются эвристически по названию, это не каталог применяемости к автомобилям.
Главная показывает реальные бренды и категории прайса. На страницах указаны дата загрузки и
дата файла поставщика (`Last-Modified`, для локального файла — время из имени CSV в поясе сайта).
Прайс старше суток помечается. Кнопка «Цены и сроки» запрашивает свежие предложения по API,
после чего можно выбрать предложение и добавить его в корзину. Наценка +15%, сроки +1 день.

## Подбор по VIN

Следующий источник подбора — CarsCats (решение от 30.10.2026). Доступа пока нет.
На https://poisk.vin/ описано подключение к каталогам через удалённый рабочий стол;
публичная документация API/виджета пока не найдена. До подключения нужны подтверждение
возможности встраивания в сайт, документация и тестовый доступ от поставщика.
VIN-поиск пока остаётся недоступным; прайс склада не содержит применяемости по VIN.

## Регистрация, корзина, заказы

- Регистрация и вход: `/register`, `/login`, выход `POST /logout`. Пароли хэшируются scrypt (стандартная
  библиотека), сессия — подписанная cookie (`SECRET_KEY` в `.env`, обязательно сменить на проде).
- Корзина работает и без входа (токен в cookie-сессии); после входа анонимная корзина переезжает к клиенту.
  Цена позиции берётся из кэша предложений на сервере, а не из запроса браузера.
- Оформление `/checkout` доступно после входа: самовывоз или доставка, контакт, комментарий. Заказ получает
  номер `DAP-#####`, позиции фиксируют цену поставщика и цену клиента. Оплата по счёту, онлайн-оплаты нет.
- Каждый заказ клиента передаётся в autoeuro от нашего аккаунта (`POST /create_order/`, позиции по `offer_key`).
  Отправка идёт в фоне сразу после оформления; неудачные попытки повторяет цикл раз в
  `SUPPLIER_ORDERS_RETRY_MINUTES` минут (до `SUPPLIER_ORDERS_MAX_ATTEMPTS` раз, заказы не старше 3 дней),
  вручную: `uv run python -m scripts.resend_orders`. Технический статус и номер поставщика видны менеджеру; покупатель видит только «В работе».
- Защита: `SUPPLIER_ORDERS_ENABLED=false` по умолчанию. Включать только на боевом сервере: каждая отправка
  создаёт настоящий заказ и списывает баланс в autoeuro. Плательщик — `AUTOEURO_PAYER_KEY` или первый из `/get_payers`.
- Демо-клиент для локальной разработки создаётся сидом, логин и пароль в `scripts/seed.py`.

### Перепроверка перед оформлением

При каждом подтверждении `/checkout` сервер заново запрашивает предложения поставщика
по бренду и артикулу, без кэша и аналогов. Для одинаковой пары в одном оформлении
выполняется один запрос. Проверяется именно выбранный `offer_key`; другой товар или склад
автоматически не подставляется. Наценка +15% и срок +1 день сохраняются.

- Если клиентская цена или календарная дата поставки изменились, новые условия сохраняются
  в корзине, заказ не создаётся. Покупатель видит изменения и должен подтвердить заказ ещё раз;
  повторное подтверждение снова запрашивает поставщика. Суммы на оформлении показаны с копейками.
- Если предложение исчезло, источник сменился, остатка недостаточно, нарушена кратность
  отгрузки или цена некорректна/не в рублях, оформление блокируется (HTTP 409).
  Корзина сохраняется; количество или состав нужно исправить в корзине, новое предложение
  выбрать через поиск. При блокирующей проблеме изменения цен остальных позиций не сохраняются.
- Если API поставщика недоступен, оформление возвращает HTTP 503 с предложением повторить
  попытку. Заказ и фоновая отправка не создаются; введённые данные формы остаются на странице.
- Перед созданием заказа PostgreSQL блокирует строку клиента и выбранные строки корзины,
  чтобы последовательные подтверждения одного клиента не создавали заказ из одной корзины дважды.

Это проверка состояния на момент ответа API, а не резервирование: цена и остаток могут измениться
между проверкой и фактическим принятием заказа поставщиком. При смене `offer_key` покупателю
потребуется выбрать предложение заново. Сверяется календарная дата `delivery_time` в часовом поясе
сайта; отдельное подтверждение изменения времени внутри того же дня не требуется.

Проверки (без реального API и заказов):

```bash
uv run pytest -q
uv run ruff check .
git diff --check
```

Если `uv` недоступен в SSH PATH, используйте уже установленное окружение:
`.venv/bin/python -m pytest -q` и `.venv/bin/ruff check .`.

## Кабинеты и взаиморасчёты

- `/garage`: добавление, редактирование и удаление автомобилей. VIN можно сохранить вручную,
  но внешнего подбора нет. Удаление автомобиля сохраняет связанные сметы без привязки.
- `/estimates`: создание и редактирование смет с автомобилем, запчастями и работами.
  У позиции — наименование, необязательный артикул, целое количество и цена с копейками.
  Сумма пересчитывается сервером. Позиции редактируются только в черновике; подтверждённую
  или закрытую смету можно вернуть в черновик. Есть удаление и печать. Смета не оформляет
  заказ поставщику и не означает резервирования или актуальной цены из API.
- `/settlements`: начисления по заказам, учтённые оплаты, задолженность или аванс.
  Отменённые менеджером заказы исключаются из начислений. Оплаты записываются менеджером
  вручную по подтверждённому поступлению; банковской синхронизации, счетов и подписанных
  актов сверки нет. Отображаемая сводка — данные сайта.
- `/manager`: клиенты с контактами, последние 200 заказов, детали заказа и технический статус
  передачи поставщику. Менеджер может менять внутренний статус и контакт назначенного менеджера,
  регистрировать полученную оплату и сторнировать её с обязательной причиной.
  Уникальный номер документа на клиента защищает от повторной записи оплаты.
  Оплаты неизменяемы: исправление — отдельная отрицательная запись с сохранением истории.
- Покупателю в списке и деталях заказа показывается только **«В работе»** независимо от
  внутреннего статуса. Ошибки API, номер заказа поставщика и настройки отправки ему не выводятся.
  Поставщик самой детали по-прежнему виден. Отмена на сайте не отменяет заказ в Автоевро;
  менеджер должен отдельно решить это у поставщика. Отменённые заказы не отправляются повторно.
- Все суммы теперь показываются с копейками; денежные итоги считаются через Decimal.
  Новые изменяющие формы защищены токеном сессии; доступ к данным проверяется по владельцу,
  доступ к менеджерским маршрутам — по роли. Роль не выдаётся при регистрации.

Миграция: `uv run alembic upgrade head` (новая ревизия `a19b02c3d4e5`).
Назначение/отзыв роли: `python -m scripts.set_manager EMAIL [--revoke]` — только
для уже зарегистрированного согласованного аккаунта. Сейчас выдача роли отложена пользователем.

Подготовка production: [deploy/README.md](deploy/README.md), шаблоны systemd/nginx и
проверяемые настройки HTTPS-cookie и допустимых хостов. Сервер и домен пока не выбраны,
выкладка не выполнялась.

Проверка конкурентного оформления на PostgreSQL (без API, во временной схеме с очисткой):

```sh
uv run python -m scripts.check_checkout_concurrency
```

## Структура

```
app/
  main.py              приложение FastAPI
  config.py            настройки из .env
  db.py, models.py     подключение и модели SQLAlchemy
  routers/pages.py     HTML-страницы
  routers/catalog.py   каталог по прайсу, бренды, категории и поиск
  routers/auth.py      регистрация, вход, выход
  routers/cart.py      корзина и оформление заказа
  routers/api.py       JSON API (/api/v1)
  services/auth.py     пароли и проверка регистрации
  services/cart.py     корзина, слияние после входа, создание заказа
  services/pricing/    источники цен: base (контракт), autoeuro, demo, service (кэш)
  services/pricelist/  импорт прайса, расписание, категории и запросы каталога
  services/supplier_orders.py  передача заказов в Автоевро и повторы
  templates/, static/  шаблоны и стили по макету
alembic/               миграции
scripts/seed.py        начальные данные
scripts/import_pricelist.py  ручной запуск импорта прайса
scripts/resend_orders.py  повторная отправка заказов (реальная при включённой отправке)
tests/                 проверки логики и HTTP-сценариев без реального API
```
